1. Executive Summary & Architectural Overview
This technical documentation outlines the deployment of the production-ready Trendify E-Commerce Application utilizing a modern GitOps continuous integration and continuous delivery (CI/CD) ecosystem. The infrastructure plane is orchestrated dynamically across Amazon Web Services (AWS) using infrastructure-as-code principles, hosted on a managed Amazon Elastic Kubernetes Service (EKS) cluster, and continuously validated via automated delivery pipelines.
Global Port, Service, and Firewall Mapping Matrix
To preserve security boundaries and prevent unauthorized public ingress while operating within budget limits, the following network configuration matrix was engineered and implemented across the cluster:

| Component / Subsystem | Service Access Model | Internal Pod Port | Exposed Ingress Portal | Network Path & Tunnelling Logic |

| Jenkins Control Plane | Node Security Group | 8080 | 8080 | Public IPv4 Entry Point (44.215.106.40:8080) |
| Trendify Web App | Native ClusterIP | 3000 | 8081 | Direct local loopback tunnel (sh tunnel mapping) |
| Prometheus Core Engine | System ClusterIP | 9090 | 8081 (Swapped) | Isolated monitoring namespace endpoint boundary |
| Grafana Visual Analytics | Cloud LoadBalancer | 3000 | 8081 (Swapped) | Ingress visualization layer via service port metrics |

## 3. Automated Declarative Pipeline Script (Jenkinsfile)
This multi-stage execution framework integrates automated workspace sanitization, secure Docker CLI shell login mechanisms via tokenization blocks, and automated Kubernetes synchronization states leveraging the modern AWS CLI v2 plugin.

pipeline {
    agent any
    environment {
        DOCKER_HUB_REGISTRY = "namodharani/trend-app"
        AWS_REGION          = "us-east-1"
        EKS_CLUSTER_NAME    = "trend-cluster"
    }
    stages {
        stage('Pull Codebase') {
            steps {
                cleanWs()
                checkout scm
            }
        }
        stage('Docker Image Build') {
            steps {
                script {
                    sh "docker build -t ${DOCKER_HUB_REGISTRY}:${BUILD_NUMBER} ."
                }
            }
        }
        stage('DockerHub Registry Push') {
            steps {
                script {
                    withCredentials([usernamePassword(credentialsId: 'dockerhub-credentials-id', usernameVariable: 'DOCKER_USER', passwordVariable: 'DOCKER_PASS')]) {
                        sh "echo \$DOCKER_PASS | docker login -u \$DOCKER_USER --password-stdin"
                        sh "docker tag ${DOCKER_HUB_REGISTRY}:${BUILD_NUMBER} ${DOCKER_HUB_REGISTRY}:latest"
                        sh "docker push ${DOCKER_HUB_REGISTRY}:${BUILD_NUMBER}"
                        sh "docker push ${DOCKER_HUB_REGISTRY}:latest"
                    }
                }
            }
        }
        stage('Kubernetes Infrastructure Sync') {
            steps {
                script {
                    sh "sed -i 's|namodharani/trend-app:.*|${DOCKER_HUB_REGISTRY}:${BUILD_NUMBER}|g' k8s/deployment.yaml"
                    sh "aws eks update-kubeconfig --region ${AWS_REGION} --name ${EKS_CLUSTER_NAME}"
                    sh "kubectl apply -f k8s/deployment.yaml"
                    sh "kubectl apply -f k8s/service.yaml"
                }
            }
        }
    }
}
